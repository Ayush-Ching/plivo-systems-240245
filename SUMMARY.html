System Architecture & Design Summary

1. Overview

The system was designed to beat a highly unstable network (Profile B) within strict 110ms deadlines (the lowest valid delay) and a hard 2.00x bandwidth overhead limit. We achieved this using a dual-layered resilience strategy: Interleaved Forward Error Correction (FEC) combined with a Budgeted Dynamic ARQ (NACK) mechanism.

2. Asynchronous Core (System Level)

Both sender.cpp and receiver.cpp were rewritten to operate as purely asynchronous, non-blocking state machines using fcntl and select() loops operating on 1ms boundaries. This ensures that socket reads never block the absolute T0 timelines required for playout judging.

3. Interleaved XOR FEC (The First Line of Defense)

Rather than simple adjacent XOR blocks which fail on burst drops, we implemented an interleaved sliding window: FEC(n) = Data(n-1) ^ Data(n-3). This separates the packets into two mathematically independent streams (Odds and Evens). A consecutive burst drop of 2 packets now mathematically isolates to one missing packet per stream, allowing perfect reconstruction without requesting NACKs. The sender transmits this FEC on 95% of frames, locking our proactive bandwidth investment at exactly 1.95x.

4. Budgeted Dynamic NACKs (The Fallback)

For drops that escape the FEC window, we implemented a feedback loop. The receiver tracks network jitter using a TCP-like EWMA (Exponentially Weighted Moving Average) of RTT variance (srtt and rttvar) relative to the harness's T0 clock. Instead of waiting for gaps, it mathematically predicts when a packet is officially "lost" versus "delayed" and fires a NACK. To mathematically guarantee we never breach the 2.00x bandwidth limit in hostile jitter spikes, a hard lifetime budget of 25 NACKs was introduced.
